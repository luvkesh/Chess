# Chackmate for Unity (starter)

The native apps (iOS, Android, desktop) are planned in Unity. This folder is the starting point, not a finished client.

## What is here

- `Packages/com.chacklate.core/` is a Unity package with no engine references, so it also builds as plain .NET.
  - `Rules.cs` is a C# port of the game rules in `packages/chess-core`: FEN in and out, legal moves, SAN, check, mate, stalemate, castling, en passant, promotion, repetition, the 50-move and 75-move rules, and insufficient material.
  - `Online.cs` is a client for `services/game-server`. It speaks the same WebSocket protocol as the web game: sign in or play as a guest, seek a game, play moves, and handle clocks, draws, resigns, resyncs and results.
  - `Json.cs` is a small JSON reader and writer for that protocol.
- `Assets/Scripts/` holds two sample scripts. `BoardView` draws a board from primitives and takes clicks. `OnlineMatch` connects, seeks a game and plays it on that board.
- `Tests/` runs the core package under plain .NET 8.

## What is verified, and what is not

Verified in CI (the "Unity core" job):

- Perft counts on the standard test positions match the published numbers.
- 40 reference games (about 4,500 moves) generated by the JavaScript rules give the same FEN, legal moves in SAN, repetition counts, draw claims and result after every move.
- Two C# clients play a full game against a real game server.

Not verified yet:

- The scripts in `Assets/Scripts/` have not been compiled or run in the Unity editor, because no Unity licence or editor is available in this build environment. Open the project with Unity 6 (6000.0.23f1 or later) and expect small fixes.
- No art, animation, sound, menus, store or progression. Those exist in the web game and still need to be built here.
- WebGL builds cannot use `System.Net.WebSockets`. The web game already covers the browser, so this client targets iOS, Android and desktop.

## Run the tests

```sh
node apps/unity/Tests/fixtures.js > apps/unity/Tests/Chacklate.Core.Tests/fixtures.json
cd apps/unity/Tests/Chacklate.Core.Tests
dotnet run -c Release
# With a server running locally, also play a live game:
CHACKLATE_SERVER=ws://127.0.0.1:8080/ws dotnet run -c Release
```

## Unity Cloud project

The project is linked to the Unity Cloud project **Chess** (project ID `b6fd69f8-9193-4b5b-9026-204352ecf4d4`) through `ProjectSettings/ProjectSettings.asset`. Unity fills in the rest of that file the first time the editor opens it; commit the result. If the editor asks you to link the project, pick the same project and organisation.

The project is marked as **directed to children** (COPPA). That means:

- no personalised ads and no ad identifiers;
- Unity Analytics must stay in its child-directed mode, without collecting device identifiers;
- no open text chat between players (the game only has preset reactions);
- any sign-up that collects an email needs parental consent for players under 13.

Firebase is not linked, and none of this needs it.

## Open in Unity

1. Open `apps/unity` with Unity Hub.
2. Make a scene with an empty GameObject and add `OnlineMatch` to it. Set the server URL, for example `ws://127.0.0.1:8080/ws`.
3. Press Play. The status line shows the connection, the seek and the game.
